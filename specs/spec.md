# RemoteConnect — спецификация

**Статус:** утверждена
**Дата:** 2026-10-23
**Версия:** 0.2 — добавлены FR-NET-11, FR-SEC-9, FR-SEC-10, уточнён FR-SEC-4

---

## 1. Назначение

RemoteConnect — десктопное приложение для Windows, которое позволяет удалённо видеть экран другого компьютера и управлять им мышью и клавиатурой. Работает напрямую между двумя компьютерами, без сторонних серверов. Предназначено для использования среди знакомых людей (друзей), а не как публичный сервис.

## 2. Термины

| Термин | Значение |
|---|---|
| **Хост** | Компьютер, который ожидает входящее сетевое подключение (у которого открыт порт). |
| **Клиент** | Компьютер, который инициирует сетевое подключение к хосту по `IP:порт`. |
| **Управляемая сторона** | Компьютер, чей экран транслируется и которым управляют. |
| **Управляющая сторона** | Компьютер, который смотрит экран и отправляет ввод. |
| **Сессия** | Период от подтверждения доступа до отключения. |

Сетевая роль (хост/клиент) и роль в сессии (управляющая/управляемая) **независимы**: любая из сторон может быть управляемой независимо от того, кто к кому подключился.

## 3. Цели и не-цели

### 3.1 Цели (v1)
- Подключение двух ПК через интернет без собственного сервера: один ПК — хост с открытым портом.
- Настройка хоста прямо в приложении, без ручной настройки роутера (если роутер поддерживает UPnP).
- Трансляция экрана и управление мышью/клавиатурой.
- Защита доступа паролем и обязательное подтверждение на управляемой стороне.
- Шифрование всего трафика.

### 3.2 Не-цели (v1)
- Передача файлов, буфер обмена, звук, чат.
- Relay/сигнальный сервер, подключение по ID.
- Работа за CGNAT (серый IP) без внешних средств.
- Кроссплатформенность (только Windows).
- Неконтролируемый доступ: подключение без участия человека на управляемой стороне, автозапуск, работа в виде службы, скрытый режим. **Приложение намеренно не поддерживает эти сценарии.**
- Управление экраном входа в Windows, окнами UAC и Ctrl+Alt+Del (требует службы с правами SYSTEM).

## 4. Пользовательские сценарии

### С1. Настройка хоста (один раз)
1. Пользователь А открывает вкладку «Хост», нажимает «Начать ожидание».
2. Приложение открывает порт на роутере через UPnP, определяет внешний IP, проверяет доступность.
3. Приложение показывает строку подключения `203.0.113.5:47800` и кнопку «Скопировать».
4. А отправляет строку другу Б любым мессенджером вместе с паролем.

### С2. Друг подключается, А управляет компьютером Б
1. Б на вкладке «Подключиться» вводит строку и пароль, выбирает режим «Разрешить управление моим ПК», нажимает «Подключиться».
2. Соединение устанавливается, пароль проверяется.
3. У Б открывается окно подтверждения: «Пользователь А получит доступ к экрану и управлению. Разрешить?». Б нажимает «Разрешить».
4. У А открывается окно с экраном Б. А управляет мышью и клавиатурой.
5. У Б всё время сессии видна плашка «Ваш компьютер под управлением» с кнопкой «Отключить».

### С3. Друг подключается, Б управляет компьютером А
Как С2, но Б выбирает режим «Управлять удалённым ПК». Подтверждение появляется у А (на хосте), плашка — тоже у А.

### С4. Завершение сессии
Любая сторона нажимает «Отключить» или закрывает приложение → сессия завершается у обеих сторон, обе видят уведомление.

### С5. Хост недоступен извне
UPnP не сработал или обнаружен серый IP → приложение показывает понятную причину и что делать (включить UPnP в роутере / пробросить порт вручную / использовать Tailscale или ZeroTier).

## 5. Функциональные требования

Приоритеты: **M** — обязательно в v1, **S** — желательно в v1, **C** — можно позже.

### 5.1 Хост и сеть
| ID | Требование | Приоритет |
|---|---|---|
| FR-NET-1 | Хост слушает TCP-порт, по умолчанию 47800, порт настраивается. | M |
| FR-NET-2 | При старте ожидания хост пытается открыть порт на роутере через UPnP (IGD) и закрывает его при остановке/выходе. | M |
| FR-NET-3 | Приложение определяет внешний IP: через UPnP у роутера и через публичный сервис определения IP. | M |
| FR-NET-4 | Если внешний IP роутера отличается от публичного IP или лежит в диапазоне 100.64.0.0/10 / частных диапазонах — приложение сообщает о вероятном CGNAT (С5). | M |
| FR-NET-5 | Приложение показывает строку подключения `IP:порт` и копирует её в буфер обмена по кнопке. | M |
| FR-NET-6 | Приложение показывает локальные IP-адреса (для подключения внутри одной сети / через Tailscale). | S |
| FR-NET-7 | Приложение добавляет правило брандмауэра Windows для своего порта (с запросом прав администратора, если нужно). | S |
| FR-NET-8 | Проверка доступности порта извне. Метод — см. открытый вопрос В1. | S |
| FR-NET-9 | Клиент подключается по `IP:порт` или `hostname:порт`; таймаут подключения 10 с с понятным сообщением об ошибке. | M |
| FR-NET-10 | Хост принимает одновременно только одну сессию; остальные подключения отклоняются с сообщением «Занято». | M |
| FR-NET-11 | Авто-остановка ожидания: если за заданное время (по умолчанию 30 мин, настраивается, можно отключить) никто не начал сессию, хост останавливает ожидание и закрывает порт на роутере. Во время активной сессии таймер не идёт и перезапускается после её окончания. | M |

### 5.2 Безопасность и доступ
| ID | Требование | Приоритет |
|---|---|---|
| FR-SEC-1 | Весь трафик шифруется TLS 1.3. Хост использует самоподписанный сертификат, создаваемый при первом запуске. | M |
| FR-SEC-2 | Доступ защищён паролем, который задаёт пользователь хоста. Пароль не передаётся открытым текстом (проверка challenge-response внутри TLS). | M |
| FR-SEC-3 | Пароль хранится локально только в виде хэша (PBKDF2/Argon2) или защищённым через DPAPI. | M |
| FR-SEC-4 | После 5 неверных паролей с одного IP — блокировка этого IP на 5 минут; блокировка снимается автоматически. Учитываются только неверные пароли (не таймауты и обрывы). Клиент получает понятное сообщение: «Неверный пароль, осталось попыток: N» или «Слишком много попыток, повторите через M мин». | M |
| FR-SEC-5 | Управляемая сторона **всегда** показывает окно подтверждения перед началом сессии. Без явного «Разрешить» трансляция и ввод не начинаются. Окно автоматически отклоняет запрос через 60 с. | M |
| FR-SEC-6 | На управляемой стороне во время сессии постоянно видна поверх всех окон плашка «Ваш компьютер под управлением: <имя>» с кнопкой «Отключить». Плашку нельзя скрыть, пока идёт сессия. | M |
| FR-SEC-7 | Обе стороны видят отпечаток сертификата (короткий код), чтобы при желании сверить его голосом. | S |
| FR-SEC-8 | Управляемая сторона может временно запретить ввод (оставить только просмотр) кнопкой на плашке. | S |
| FR-SEC-9 | Вкладка «Хост» показывает список заблокированных IP с оставшимся временем блокировки и кнопкой «Разблокировать» для каждого. | M |
| FR-SEC-10 | Режим пароля на хосте: «Постоянный» (задаёт пользователь) или «Одноразовый» (при каждом запуске ожидания генерируется новый пароль вида `k7m-29x`, показывается рядом со строкой подключения и копируется вместе с ней). По умолчанию — одноразовый. | M |

### 5.3 Трансляция экрана
| ID | Требование | Приоритет |
|---|---|---|
| FR-SCR-1 | Захват основного монитора управляемой стороны. | M |
| FR-SCR-2 | Передаются только изменившиеся области кадра; сжатие JPEG с настраиваемым качеством. | M |
| FR-SCR-3 | Отображение курсора удалённой стороны. | M |
| FR-SCR-4 | Окно просмотра масштабирует изображение под размер окна с сохранением пропорций; есть полноэкранный режим. | M |
| FR-SCR-5 | Переключение между мониторами управляемой стороны. | S |
| FR-SCR-6 | Адаптация качества/частоты кадров под пропускную способность канала. | C |

### 5.4 Ввод
| ID | Требование | Приоритет |
|---|---|---|
| FR-INP-1 | Перемещение мыши, нажатия левой/правой/средней кнопки, колесо прокрутки. Координаты пересчитываются с учётом масштаба окна. | M |
| FR-INP-2 | Клавиатура: нажатия и отпускания клавиш, включая модификаторы (Ctrl, Alt, Shift, Win) и сочетания. | M |
| FR-INP-3 | Ввод передаётся, только пока окно просмотра в фокусе. При потере фокуса все зажатые клавиши/кнопки отпускаются на удалённой стороне. | M |
| FR-INP-4 | Сочетания, которые перехватывает сама Windows (Alt+Tab, Win), передаются на удалённую сторону, когда окно просмотра активно. | S |

## 6. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-1 | Платформа: Windows 10 1903+ и Windows 11, x64. |
| NFR-2 | Стек: .NET 10, WPF. |
| NFR-3 | Поставка: один exe (self-contained, single-file), без установщика, без прав администратора для обычной работы. |
| NFR-4 | Задержка «действие → изображение» не более 200 мс в локальной сети и не более 400 мс через интернет при канале 10 Мбит/с. |
| NFR-5 | Не менее 15 кадров/с при 1920×1080 и активном изменении экрана на канале 10 Мбит/с; при статичном экране трафик близок к нулю. |
| NFR-6 | Загрузка CPU на управляемой стороне — не более 15% на 4-ядерном ПК при 15 кадрах/с. |
| NFR-7 | При обрыве соединения обе стороны в течение 10 с показывают «Соединение потеряно»; управляемая сторона сразу прекращает приём ввода. |
| NFR-8 | Логи — в `%LOCALAPPDATA%\RemoteConnect\logs`, без паролей и содержимого экрана. |
| NFR-9 | Поддержка DPI-масштабирования (100–200%) на обеих сторонах. |

## 7. Ограничения и допущения

- Хост должен иметь белый IP. Если UPnP недоступен — пользователь пробрасывает порт вручную, приложение подсказывает как.
- Окна, запущенные от администратора, не принимают ввод от приложения, запущенного без прав администратора (UIPI). Поэтому есть опция «Перезапустить от администратора» на управляемой стороне (S).
- Защищённый рабочий стол (UAC, Ctrl+Alt+Del, экран блокировки) в v1 не транслируется и не управляется.

## 8. Открытые вопросы

| ID | Вопрос | Предложение |
|---|---|---|
| В1 | Как проверить доступность порта извне без своего сервера? | Попробовать подключиться к своему внешнему IP (работает, если роутер поддерживает hairpin NAT); если не получилось — показать «не удалось проверить», а не «недоступен». |
| В2 | Пароль постоянный или одноразовый на каждый запуск хоста? | **Решено:** оба режима, по умолчанию одноразовый (FR-SEC-10). |
| В3 | Как защититься от подмены хоста (MITM) с самоподписанным сертификатом? | v1: показ отпечатка (FR-SEC-7) + запоминание сертификата при первом подключении (TOFU) с предупреждением при смене. |
| В4 | Нужен ли H.264 вместо JPEG? | v1: JPEG по изменённым блокам (проще). H.264 через Media Foundation — кандидат на v2 при недостатке производительности. |

## 9. Критерии приёмки v1

1. Два ПК в разных домашних сетях: хост с UPnP-роутером и белым IP, клиент — за обычным NAT. Сценарии С1–С4 выполняются без ручной настройки роутера.
2. Без правильного пароля сессия не начинается; после 5 ошибок IP блокируется на 5 минут, клиент видит оставшиеся попытки и время блокировки, хост может снять блокировку вручную.
2a. Если никто не подключился за время авто-остановки, порт на роутере закрывается (проверяется в веб-интерфейсе роутера или через UPnP-клиент).
3. Без нажатия «Разрешить» на управляемой стороне экран не транслируется и ввод не выполняется.
4. Плашка сессии видна всё время сессии; «Отключить» на ней завершает сессию у обеих сторон.
5. В Wireshark трафик зашифрован (TLS), пароль не виден.
6. Набор текста, сочетания клавиш, перетаскивание мышью и прокрутка работают в Блокноте и браузере на удалённой стороне.
7. Выполняются NFR-4, NFR-5 в локальной сети.
8. При CGNAT приложение показывает понятное сообщение (С5).
