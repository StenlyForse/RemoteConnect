## 1. Как это работает — общая схема

Чат идёт **по тому же TLS-соединению**, что экран, ввод и буфер обмена: отдельного сокета, сервера или WebSocket нет.
Сообщение чата — ещё один тип сообщения протокола (`ChatMessage`), как `ClipboardData`.

```
УПРАВЛЯЮЩИЙ (окно просмотра)                         УПРАВЛЯЕМЫЙ (плашка)
────────────────────────────                         ────────────────────
ChatPanel: Enter в поле ввода
ChatSession.Send(text):
  ChatText.Normalize → проверка лимита
  connection.Send(ChatMessage) — обычная очередь
  добавить в свою историю (Mine)
  ── ChatMessage(text) ── TLS ─────────────────────►  цикл приёма → ChatSession.TryHandle
                                                      ChatText.Normalize + лимит (иначе — отклонить, журнал)
                                                      добавить в историю (Theirs, время получения)
                                                      первое сообщение и панель свёрнута, не сворачивали
                                                      вручную → раскрыть без активации окна;
                                                      иначе → красная точка + мигание плашки
```

История — список в памяти объекта `ChatSession`, который живёт ровно столько, сколько сессия
(создаётся вместе с окном просмотра / плашкой, удаляется при их закрытии).

## 2. Технические решения

| Область | Решение | Почему |
|---|---|---|
| Транспорт | Новое сообщение `ChatMessage(string Text)` в существующем `Connection`, **обычная** (не фоновая) очередь | NFR-CHT-1: кадр файла ждёт не дольше одного чанка 64 КБ — сообщение обгоняет передачу файлов |
| Размер | Текст — UTF-8 с длиной-префиксом, отдельный лимит 16 КБ байт при разборе (сейчас строки протокола ≤ 1 КБ); после декодирования — ≤ 4 000 символов UTF-16 | FR-CHT-3 |
| Нормализация | `ChatText.Normalize`: `\r\n`/`\r` → `\n`; удаляются управляющие символы кроме `\n`, `\t` и символы управления направлением текста (U+202A–202E, U+2066–2069, U+200E/F) — чтобы ссылку нельзя было визуально «перевернуть»; обрезка пробелов по краям | FR-CHT-2, FR-CHT-15 |
| Ссылки | `ChatLinkParser` (Core) разбивает текст на фрагменты «текст/ссылка». Ссылка — только `http://`/`https://` до пробела; хвостовая пунктуация `.,;:!?»"'` и несбалансированная `)` отрезаются; результат проверяется `Uri.TryCreate(Absolute)` и схемой ещё раз | FR-CHT-13, FR-CHT-15 |
| Открытие ссылки | `Process.Start(new ProcessStartInfo(uri.AbsoluteUri) { UseShellExecute = true })` — только для `Uri` со схемой http/https, повторная проверка прямо перед запуском | FR-CHT-14, FR-CHT-15 |
| История | `ChatSession.Messages` — `ObservableCollection<ChatEntry>` (кто, имя, время, фрагменты) на UI-потоке; не больше **1 000** сообщений, старые удаляются из начала. В журнал пишется только «чат: сообщение N символов», не текст | FR-CHT-6 |
| Отображение сообщения | Каждое сообщение — `RichTextBox` только для чтения (`IsReadOnly`, `IsDocumentEnabled` — чтобы `Hyperlink` кликались) с `FlowDocument` из фрагментов; выделение мышью и Ctrl+C работают штатно. Своё контекстное меню: «Копировать»; на `Hyperlink` — «Копировать ссылку» | FR-CHT-12, FR-CHT-14 |
| Поле ввода | `TextBox`, `AcceptsReturn`, `MaxLength = 4000`, `TextWrapping`; Enter перехватывается в `PreviewKeyDown` (без Shift — отправить). Стандартное контекстное меню WPF уже даёт «Вырезать/Копировать/Вставить»; добавляется «Выделить всё» | FR-CHT-9, FR-CHT-11 |
| Ввод у управляющего | Глобальный перехват клавиатуры (`LowLevelKeyboardHook.OnKey`) сейчас отправляет все клавиши, пока окно просмотра активно. Добавляется условие: если фокус клавиатуры внутри панели чата — клавиша не перехватывается (`return false`). При входе фокуса в чат отправляется `ReleaseAll`. Клик по экрану уже вызывает `Screen.Focus()` — ввод возвращается сам | FR-CHT-10 |
| Сужение экрана | Окно просмотра: `Surface` и панель чата — в `Grid` с двумя колонками; колонка чата `Auto`, панель 320 px, `Collapsed` по умолчанию. Изображение `Stretch=Uniform`, а координаты мыши уже считаются от `Screen.ActualWidth/Height` — пересчёт выходит сам | FR-CHT-16, FR-CHT-17 |
| Панель у управляемого | Внутри того же окна плашки (`SessionBarWindow`): плашка и панель под ней в вертикальном `StackPanel`, панель прижата вправо. Так панель — поверх всех окон и двигается вместе с плашкой без отдельного окна | FR-CHT-20 |
| Раскрытие без фокуса | Окно плашки уже `ShowActivated=False`; раскрытие — только смена `Visibility`, без `Activate()`/`Focus()`. Проверяется автотестом: активное окно до и после входящего сообщения то же | FR-CHT-21, FR-CHT-22 |
| Мигание | `ColorAnimation` фона плашки (красный → светлый → красный, ~0,6 с, один раз) | FR-CHT-24 |
| Общий UI | `ChatPanel` — один `UserControl` для окна просмотра и плашки; `ChatSession` — общая логика | Одна реализация на обе стороны |
| Версия в окне | `AppInfo.Version` — `AssemblyInformationalVersion` без части после `+`; `TextBlock` внизу главного окна | FR-VER-1 |

## 3. Протокол v4

`Handshake.ProtocolVersion = 4`. Новые сообщения:

| Тип | № | Направление | Содержимое |
|---|---|---|---|
| `AppVersion` | 26 | обе стороны, при рукопожатии | строка версии программы, ≤ 32 символа |
| `ChatMessage` | 27 | обе стороны, после «Разрешить» | текст ≤ 4 000 символов |

### Версия при рукопожатии — почему отдельное сообщение

Разборщик сообщений отклоняет лишние байты в конце сообщения (`MessageFramer`: `ms.Position != length`), а неизвестный
тип сообщения — ошибка протокола. Значит, нельзя ни дописать версию в `Hello`/`AuthResult`, ни послать v0.3 новое
сообщение: v0.3 разорвёт соединение с общей ошибкой вместо «несовместимая версия». Поэтому:

```
Клиент → Hello(ProtocolVersion, Name, Role)                — формат не меняется (как в v0.1–v0.3)
Хост:   Hello.ProtocolVersion ≥ 4 → AppVersion(свой номер)  — v0.3-клиенту не отправляется
Клиент: получил AppVersion → AppVersion(свой номер)
Хост:   протокол не совпадает → AuthResult(VersionMismatch), иначе → AuthChallenge…
```

| Хост ↔ клиент | Что видит хост | Что видит клиент |
|---|---|---|
| 0.4 ↔ 0.4 | — (совместимы) | — |
| 0.4-хост ↔ 0.3-клиент | «более старая версия» (FR-VER-3) | прежнее сообщение v0.3 |
| 0.3-хост ↔ 0.4-клиент | ничего нового (v0.3) | `AuthResult(VersionMismatch)` без `AppVersion` → «более старая версия» |
| 0.4 ↔ 0.5+ | «у собеседника 0.5.0, у вас 0.4.0» | то же зеркально |

`Hello`, `AuthResult` и `AppVersion` с этой версии считаются **замороженными**: их формат и номера типов в будущих версиях
не меняются, иначе снова пропадёт понятное сообщение о версии.

Хост показывает отказ по версии в строке состояния режима ожидания (сейчас — только в журнале): `RunHostAsync`
возвращает причину отказа вместе с версией собеседника.

## 4. Компоненты

| Компонент | Проект | Ответственность | Требования |
|---|---|---|---|
| `ChatMessage`, `AppVersion` + сериализация | Core | Сообщения §3, лимиты при разборе | FR-CHT-3, FR-VER-2 |
| `Handshake` (доработка) | Core | Обмен `AppVersion`, отказ по версии с номером собеседника, `ProtocolVersion = 4` | FR-VER-2, FR-VER-3 |
| `ChatText` | Core | Нормализация и проверка текста (длина, пустота, управляющие символы) | FR-CHT-2, 3 |
| `ChatLinkParser` | Core | Разбиение на фрагменты текст/ссылка, проверка схемы | FR-CHT-13, 15 |
| `ChatSession` | Core | История, отправка, приём (`TryHandle`), счётчик непрочитанных, правило автораскрытия, события. В Core, а не в App, — чтобы покрыть автотестами; App подписывается на события и ведёт `ObservableCollection` | FR-CHT-1, 4–8, 19, 21, 23 |
| `ChatPanel` | App | `UserControl`: список сообщений, поле ввода, контекстные меню, открытие ссылок, автопрокрутка | FR-CHT-4, 7, 9, 11–14 |
| `ViewerWindow` (доработка) | App | Значок чата с точкой, колонка панели, исключение для перехвата клавиатуры | FR-CHT-10, 16–19, 23 |
| `SessionBarWindow` (доработка) | App | Значок чата с точкой, панель под плашкой, раскрытие без фокуса, мигание | FR-CHT-20–24 |
| `ControlledSession`, цикл приёма окна просмотра | App | Передача входящих сообщений в `ChatSession` перед `ClipboardSync` | FR-CHT-1 |
| `AppInfo`, `MainWindow`, `ConnectViewModel`, `HostService` | App | Версия внизу окна; тексты отказа по версии у клиента и хоста | FR-VER-1–3 |

### Правило автораскрытия (FR-CHT-21) — в `ChatSession`, с тестами
- `AutoOpenAllowed` — только у управляемого; изначально `true`.
- Входящее сообщение при свёрнутой панели: если `AutoOpenAllowed` и это первое входящее — событие «раскрыть», иначе — непрочитанные +1.
- Пользователь свернул панель сам → `AutoOpenAllowed = false` до конца сессии.
- Раскрытие (любым способом) → непрочитанные = 0.

## 5. Этапы

Каждый этап — сборка без предупреждений, зелёные тесты, локальный коммит, короткий отчёт.

### Этап 1. Протокол v4 и версия
- `AppVersion`, `ChatMessage`, сериализация, `ProtocolVersion = 4`, обмен версиями в `Handshake`.
- `AppInfo.Version`, строка версии внизу главного окна; тексты отказа по версии у клиента и на хосте.

**Тесты:** сериализация новых сообщений; текст 4 000 символов проходит, 4 001 и > 16 КБ байт — `ProtocolException`;
рукопожатие по loopback: 0.4 ↔ 0.4 успешно; имитация v0.3-клиента (`Hello` с версией 3, без `AppVersion`) — хост не
отправляет ему `AppVersion`, отвечает `VersionMismatch` в старом формате, результат «старая версия»; имитация v0.3-хоста
(сразу `AuthResult(VersionMismatch)`) — клиент получает «старая версия»; имитация v0.5 — номер собеседника виден обеим сторонам.

### Этап 2. Логика чата (Core + `ChatSession`)
- `ChatText`, `ChatLinkParser`, `ChatSession`.

**Тесты:** нормализация (`\r\n`, управляющие и bidi-символы, пробелы, пустое сообщение); ссылки: `https://example.com/a?b=1`,
ссылка в скобках и перед точкой, кириллический домен, `HTTP://` в верхнем регистре — распознаются; `file:///C:/Windows/notepad.exe`,
`javascript:alert(1)`, `ms-settings:`, `\\server\share`, `www.example.com` — нет; `ChatSession`: история, лимит 1 000,
своё/чужое, правило автораскрытия (первое сообщение, после ручного сворачивания, у управляющего — никогда), счётчик непрочитанных;
текст сообщений не попадает в журнал.

### Этап 3. Интерфейс
- `ChatPanel`, доработки `ViewerWindow` и `SessionBarWindow`, подключение `ChatSession` в обе стороны сессии.

**Тесты:** сквозной по loopback с TLS — сообщение в обе стороны во время передачи файла 20 МБ доставляется < 1 с.
С экраном (предупредить пользователя перед запуском): два экземпляра на одном ПК — Ч1–Ч4; у управляемого автораскрытие не меняет
активное окно (`GetForegroundWindow` до/после); фокус в поле чата у управляющего — текст в Блокнот на «удалённой» стороне не
попадает, после клика по экрану — попадает; контекстные меню; открытие `https`-ссылки.

### Этап 4. Документы и релиз
- README (чат, версия в окне, «v0.4 несовместима с v0.3»), `spec.md` §5.7, статус в этом плане.
- Проверка с ноутбуком по критериям приёмки 1–9, релиз v0.4.0 — вместе с пользователем.

## 6. Риски

| Риск | Что делаем |
|---|---|
| `RichTextBox` на каждое сообщение тяжёл при сотнях сообщений | Лимит 1 000; если заметно тормозит — виртуализация списка (`VirtualizingStackPanel`) или `TextBlock` с выделением через свою обработку |
| Перехват клавиатуры отпускает клавишу, нажатую до входа в чат, «наполовину» (нажатие ушло на удалённый ПК, отпускание — нет) | `ReleaseAll` при входе фокуса в чат (FR-INP-3 уже так делает при потере фокуса окна) |
| Окно плашки с `AllowsTransparency` и полем ввода — проблемы с IME/фокусом | Проверить на этапе 3 первым делом; запасной вариант — отдельное окно панели, привязанное к плашке |

| Этап | Коммит | Что проверено |
|---|---|---|
| 1. Протокол v4 и версия | см. git log | сериализация `AppVersion`/`ChatMessage`, лимиты 4 000 символов / 16 КБ / 32 символа; рукопожатие по loopback: 0.4 ↔ 0.4 (версии переданы), имитация клиента v0.3 (отказ в старом формате, без `AppVersion`), хоста v0.3 (версия собеседника неизвестна), клиента v0.5 (обе стороны видят номер) |
| 2. Логика чата | см. git log | нормализация (переводы строк, управляющие и bidi-символы, пробелы); ссылки: http/https, верхний регистр, кириллический домен, скобки и пунктуация вокруг, `Foo_(bar)`; не ссылки: `file:`, `javascript:`, `ms-settings:`, UNC и локальные пути, `www.`, `https://user@host`; `ChatSession`: своё/чужое, время, пустые и длинные, закрытое соединение, автораскрытие (первое входящее, ручное сворачивание, только один раз), непрочитанные, лимит 1 000 |
| 3. Интерфейс | см. git log | сквозной тест по TLS: файл 20 МБ целиком (SHA-256), сообщения чата в обе стороны во время передачи — все < 1 с. Два экземпляра на одном ПК (UI Automation): «Версия 0.4.0» в главном окне; панель сужает изображение (1264 → 944 px); первое сообщение раскрывает панель под плашкой, плашка не становится активной и фокус не попадает в поле чата (активным был Блокнот); ответ с переносом строки доходит; красная точка у управляющего и на плашке (снимки); после ручного сворачивания панель не раскрывается; конец сессии закрывает плашку |

Найдено при проверке:
- `RichTextBox` сам задаёт документу `PagePadding = 5,0`, а явная `PageWidth` после этого ограничивает строку — «пузыри»
  переносили короткие строки. `PageWidth` убрана, ширина элемента учитывает отступ.
- Старая ошибка (с v0.1): закрытие окна запроса доступа крестиком вызывало `Close()` у закрывающегося окна —
  необработанное исключение. Исправлено отдельным коммитом.

**Не проверено автоматически** (на одном ПК ввод «удалённой» стороны попадает на тот же рабочий стол) — проверить с ноутбуком:
клавиши в поле чата не уходят на удалённый ПК (FR-CHT-10, критерии 2–3), контекстные меню и Ctrl+C/V (критерий 6),
открытие ссылки в браузере (критерий 5, разбор ссылок покрыт автотестами), мигание плашки.

### Проверка с ноутбуком (2026-10-25)
Пользователь проверил чат между ПК и ноутбуком по настоящей сети — всё работает, включая то, что не проверялось

открывается развёрнутым, главное окно уменьшается до рабочей области. Проверено пользователем на ноутбуке.
