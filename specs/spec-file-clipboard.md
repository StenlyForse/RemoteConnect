# RemoteConnect — спецификация: файлы через буфер обмена

**Статус:** утверждена
**Дата:** 2026-10-23
**Версия:** 0.2 — требования сформулированы с точки зрения пользователя; механизм — в заметках для плана
**Связь с основной спецификацией:** расширяет [spec.md](spec.md) §5.6 «Буфер обмена» (заменяет FR-CLP-7); целевая версия приложения — v0.3.

---

## 1. Назначение

Файлы и папки, скопированные в Проводнике на одном компьютере во время сессии, можно вставить в Проводнике на другом —
так же, как в AnyDesk и RDP. Передача начинается **в момент вставки**, а не копирования: Windows показывает своё
стандартное окно копирования с прогрессом и кнопкой «Отмена».

Работает в обе стороны независимо от того, кто управляет.

## 2. Термины

| Термин | Значение |
|---|---|
| **Источник** | Компьютер, на котором файлы скопировали (Ctrl+C / «Копировать» в Проводнике). |
| **Получатель** | Компьютер, на котором файлы вставляют. |
| **Набор** | Всё, что скопировано одной операцией: файлы и папки со всем содержимым. |
| **Виртуальные файлы** | Механизм Windows, при котором в буфере лежит описание файлов, а содержимое выдаётся программой по запросу при вставке. |

## 3. Как это выглядит для пользователя

### С1. Копирование с удалённого ПК на свой
1. В окне просмотра пользователь выделяет файлы на удалённом ПК и нажимает Ctrl+C.
2. Переходит в Проводник на своём ПК и нажимает Ctrl+V.
3. Появляется стандартное окно Windows «Копирование N элементов» с прогрессом; файлы появляются в папке.

### С2. Копирование со своего ПК на удалённый
Зеркально С1: Ctrl+C у себя → Ctrl+V в Проводнике удалённого ПК через окно просмотра.

### С3. Слишком большой набор
Пользователь копирует 2 ГБ. На стороне источника появляется уведомление «Файлы не будут доступны на другом ПК:
2,0 ГБ — больше лимита 500 МБ». На получателе в буфере остаётся предыдущее содержимое.

### С4. Отмена и обрыв
Пользователь нажимает «Отмена» в окне копирования Windows — передача прекращается, частично вставленный файл
Проводник удаляет сам. При обрыве соединения Windows показывает ошибку копирования.

## 4. Функциональные требования

Приоритеты: **M** — обязательно, **S** — желательно, **C** — можно позже.

### 4.1 Копирование и предложение файлов
| ID | Требование | Приоритет |
|---|---|---|
| FR-FCB-1 | Файлы и папки, скопированные в Проводнике на источнике, сразу становятся доступны для вставки на получателе — как в AnyDesk. Копирование само по себе не передаёт содержимое файлов (оно идёт только при вставке, FR-FCB-7). | M |
| FR-FCB-2 | Папки передаются со всем содержимым, включая вложенные и пустые папки; структура сохраняется. | M |
| FR-FCB-3 | Лимит набора — **500 МБ** суммарно и **10 000** элементов. Больше — набор не предлагается, источник видит уведомление с размером (С3). | M |
| FR-FCB-4 | Описание набора строится в фоне и не блокирует интерфейс; на большом дереве папок — не дольше 5 с, иначе набор не предлагается с уведомлением. | S |
| FR-FCB-5 | Набор действует, пока на источнике не изменился буфер обмена или не закончилась сессия. После этого запросы к нему отклоняются. | M |

### 4.2 Вставка
| ID | Требование | Приоритет |
|---|---|---|
| FR-FCB-6 | На получателе набор помещается в буфер обмена как **виртуальные файлы**; вставка в Проводнике создаёт файлы и папки с исходными именами и структурой. | M |
| FR-FCB-7 | Содержимое файла запрашивается у источника **только когда Проводник начинает его читать** при вставке и передаётся потоком, без загрузки целиком в память. | M |
| FR-FCB-8 | Вставка не замораживает Проводник: используется асинхронный режим вставки Windows, прогресс и «Отмена» — в стандартном окне копирования. | M |
| FR-FCB-9 | Один и тот же набор можно вставить несколько раз (в разные папки); каждая вставка заново читает файлы у источника. | S |
| FR-FCB-10 | Дата изменения файла на получателе совпадает с исходной. | S |

### 4.3 Надёжность
| ID | Требование | Приоритет |
|---|---|---|
| FR-FCB-11 | «Отмена» в окне копирования прекращает передачу на источнике в течение 1 с. | M |
| FR-FCB-12 | Если файл на источнике удалён, переименован или заблокирован после копирования — вставка этого файла завершается ошибкой Windows, остальные файлы набора вставляются. | M |
| FR-FCB-13 | Если файл на источнике изменился после копирования (другой размер) — вставка этого файла завершается ошибкой, а не вставляет «половину». | M |
| FR-FCB-14 | При обрыве соединения во время вставки Windows сообщает об ошибке в течение 15 с; Проводник не зависает. | M |
| FR-FCB-15 | Во время передачи файлов трансляция экрана и управление продолжают работать: частота кадров падает не более чем вдвое, задержка ввода — не более +200 мс. | M |

### 4.4 Безопасность
| ID | Требование | Приоритет |
|---|---|---|
| FR-FCB-16 | Получатель может прочитать **только файлы из предложенного набора** — по их номеру в наборе. Произвольные пути с источника запросить нельзя. | M |
| FR-FCB-17 | Имена и пути файлов, пришедшие с другого ПК, проверяются на получателе: запрещены абсолютные пути, `..`, недопустимые для Windows символы и имена (`CON`, `NUL` и т.п.). Набор с такими элементами отклоняется целиком. | M |
| FR-FCB-18 | Файлы передаются только во время активной сессии (после «Разрешить») и только при включённой синхронизации буфера у обеих сторон (FR-CLP-4). Выключение синхронизации отзывает текущий набор. | M |
| FR-FCB-19 | На стороне источника при чтении его файлов получателем видно уведомление «Передача файлов: имя, прогресс» (на плашке или в окне просмотра). | S |

### 4.5 Интерфейс
| ID | Требование | Приоритет |
|---|---|---|
| FR-FCB-20 | Уведомления источника (С3, ошибки построения набора) показываются в окне просмотра / на плашке, не всплывающими окнами. | M |
| FR-FCB-21 | Перетаскивание файлов мышью между своим рабочим столом и окном просмотра (drag-and-drop). | C |

## 5. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-FCB-1 | Скорость передачи — не менее 70% пропускной способности канала при отсутствии изменений на экране. |
| NFR-FCB-2 | Память: не более 32 МБ буферов на одну передачу независимо от размера файлов. |
| NFR-FCB-3 | Протокол — версия 3; клиенты v0.2 и v0.3 вместе не работают (сообщение о несовместимой версии). |

## 6. Ограничения

- Вставка работает в Проводнике и программах, понимающих виртуальные файлы (почтовые клиенты, многие файловые менеджеры).
  Программы, которым нужны только «настоящие» пути к файлам на диске, могут вставку не принять — это ограничение механизма
  Windows, тот же эффект есть в RDP.
- Лимит 500 МБ на набор (FR-FCB-3).
- Файлы в облачных папках «только онлайн» (OneDrive) на источнике будут сначала скачаны Windows при чтении — это может замедлить вставку.

## 7. Открытые вопросы

| ID | Вопрос | Предложение |
|---|---|---|
| ВФ1 | Нужен ли запасной путь для программ без поддержки виртуальных файлов? | Не в v0.3. Если окажется нужен — опция «скачать набор во временную папку» с обычными путями. |
| ВФ2 | Передавать ли атрибуты «только чтение» / «скрытый»? | Нет, только дату изменения (FR-FCB-10). |
| ВФ3 | Что показывать, если на получателе нет места на диске? | Ошибку выдаёт сам Проводник; дополнительно ничего не делаем. |

## 8. Заметки для плана (не требования)

- Как и в AnyDesk/RDP, при копировании на получателя передаётся только список файлов (имена, размеры, структура папок) —
  он нужен Windows, чтобы показать файлы в буфере и окно копирования. Содержимое — только при вставке.

## 9. Критерии приёмки

1. С1 и С2 между двумя ПК: файл 300 МБ, папка с 3 уровнями вложенности и пустой подпапкой, файл с кириллицей в имени — вставляются корректно, содержимое совпадает побайтно (SHA-256).
2. Содержимое файлов передаётся только при вставке: если скопировать 300 МБ и не вставлять, трафик почти не растёт.
3. «Отмена» в окне копирования останавливает передачу на источнике в течение 1 с (FR-FCB-11).
4. Удалённый после копирования файл даёт ошибку только для него; остальные вставлены (FR-FCB-12).
5. Обрыв сети посреди вставки: ошибка Windows в течение 15 с, Проводник отвечает (FR-FCB-14).
6. Набор 600 МБ не предлагается, источник видит уведомление (С3).
7. Подделанный список файлов с `..\..\Windows\evil.dll` отклоняется получателем (FR-FCB-17) — проверяется автотестом.
8. Запрос файла с номером вне набора или по устаревшему набору отклоняется источником (FR-FCB-5, FR-FCB-16) — проверяется автотестом.
9. Во время передачи 300 МБ окно просмотра обновляется, мышь и клавиатура работают (FR-FCB-15).
